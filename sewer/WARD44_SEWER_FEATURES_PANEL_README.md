# Ward44 Sewer Features Panel — `ward44_sewer_features_panel_2010_2018.csv`

Generated by `build_ward44_year_panel_2010_2018.py`. One row per `(ward, year)` — 44 Toronto wards (the **old ward system**, in effect through 2018-11-30) × 9 years (2010-2018) = **396 rows**, 0 nulls. `ward_id` = `area_short_code` from `before_2018_ward_location.csv`, zero-padded to 2 digits (e.g. `1` → `"01"`). `ward_name` = `area_desc` (e.g. `"Etobicoke North (1)"`) — `area_name` alone repeats across ward pairs (wards 1 and 2 are both "Etobicoke North"), so `area_desc` is used instead to keep each row's name unique. `ward_year` = `f"ward_{ward_id}_year_{year}"` (e.g. `"ward_27_year_2014"`).

Source datasets (Toronto Open Data): [Sewer Gravity Main](https://open.toronto.ca/dataset/sewer-gravity-mains/), [Sewer Inlets](https://open.toronto.ca/dataset/sewer-inlets/), [Sewer Manholes](https://open.toronto.ca/dataset/sewer-manholes/), [Sewer Outfalls](https://open.toronto.ca/dataset/sewer-outfalls/). Ward boundaries: `before_2018_ward_location.csv` (the pre-2018, 44-ward system; not from Toronto Open Data's City Wards dataset, which only covers the current 25-ward system).

## This is a separate file from the 25-ward panel

This file does **not** replace or merge with `ward_sewer_features_panel_2019_2023.csv` (25 wards, 2019-2023). The two use different, non-comparable ward geometries (the city moved from 44 wards to 25 wards on 2018-12-01), so a row here (`ward_27_year_2014`) is not the same spatial unit as a same-numbered row there. Joining the two into one continuous 2010-2023 time series would require a spatial crosswalk between the old and new ward boundaries — not done here, tracked as a separate pending task.

## Methodology: assigning sewer assets to ward

Same approach as `build_ward_year_panel_2019_2023.py`: for **point assets** (inlets, manholes, outfalls), test whether each point falls inside a ward polygon (`geopandas.sjoin(..., predicate="within")`). For **line assets** (pipes, which can cross a ward boundary), take the pipe's **midpoint** and test which ward polygon contains it.

The 44-ward boundaries come from `before_2018_ward_location.csv`, where each row's `geometry` column is stored as GeoJSON text rather than a native geometry type — it's parsed with `shapely.geometry.shape(json.loads(...))` and loaded as `EPSG:4326` before being reprojected to `EPSG:2952` (same metric CRS used for the 25-ward panel) to compute each ward's area.

## Why these features vary by year

Every pipe, inlet, and manhole has its own real installation date. For a row with a given `ward` and `year`, every feature below (except `dist_to_nearest_outfall_m`) is calculated using **only the pipes/inlets/manholes in that ward whose installation date is on or before that `year`** — anything installed after that `year` is simply left out of the calculation for that row. So the same ward has a different (growing) set of pipes/inlets/manholes feeding into each year's numbers: the 2010 row for a ward only "sees" what was already installed by 2010, the 2011 row "sees" everything installed by 2011 (one more year's worth), and so on through 2018.

## This file uses only `Sewer Gravity Main` (no Trunk Sewer)

Same scope decision as `ward_sewer_features_panel_2019_2023.csv` and `fsa_static_sewer_features.csv` — only `Sewer Gravity Main` is used, so every column comes from one consistent source dataset.

## Features

| Feature | What it is | How it's calculated |
|---|---|---|
| `avg_pipe_age` | Average age (years) of the ward's pipes installed by that `year`. | For every pipe in the ward with `install_year <= year`, compute `year − install_year`, then average those values. |
| `new_pipe_km` | Kilometers of pipe installed **exactly** in that row's `year` (not cumulative) — a signal of recent infrastructure investment. | Sum of `length_km` for pipes in the ward where `install_year == year` (not `<=`, only pipes installed that specific year). |
| `pct_old_pipe` | Share of the ward's installed-by-then pipe length that has already crossed the "old pipe" age threshold. | Among pipes in the ward with `install_year <= year`: `(length of those with age > 72 years) / (total length of all of them)`. The 72-year threshold is the 75th percentile of age over the whole `Sewer Gravity Main` network citywide (reference year 2026, computed once — see `FSA_INSTALL_DATE_FEATURES_README.md`), reused unchanged across all 9 years and both ward systems. |
| `cumulative_pipe_km` | Total pipe length already installed in the ward as of that `year` — a running total. | Sum of `length_km` for pipes in the ward where `install_year <= year`. Non-decreasing across years within the same ward (verified). |
| `pct_combined_sewer` | Share of the ward's installed-by-then pipe length that is "combined" type (carries both sanitary wastewater and stormwater in the same pipe), vs. "separated" systems. Combined sewers are more prone to backup during heavy storms. | Among pipes in the ward with `install_year <= year`: `(length of combined-type pipes) / (length of combined-type + separated-type pipes)`. `EO` and `FD` pipe types are excluded from this ratio. |
| `avg_pipe_diameter` | Average diameter (mm) of the ward's pipes installed by that `year`. | Mean of the `Diameter` field over pipes in the ward with `install_year <= year`. |
| `pipe_density` | Length of pipe installed by that `year`, per unit area of the ward (km of pipe per km²). | `(sum of lengths, in km, of pipes in the ward with install_year <= year) / ward area (km²)`. |
| `fd_density` | Density of Foundation Drain (FD) pipes installed by that `year`, per km² — pipes connecting house foundation drainage directly to the sewer system, a direct exposure pathway for basements. | `(length, in km, of FD-type pipes in the ward with install_year <= year) / ward area (km²)`. |
| `catch_basin_density` | Number of catch basins (inlets) installed by that `year`, per km² of the ward. | `(count of inlets in the ward with install_year <= year) / ward area (km²)`. |
| `manhole_density` | Number of manholes installed by that `year`, per km² of the ward. | `(count of manholes in the ward with install_year <= year) / ward area (km²)`. |
| `pct_combined_manholes` | Same concept as `pct_combined_sewer`, counted over manholes instead of pipe length. | Among manholes in the ward with `install_year <= year`: `(count of combined-type) / (count of combined-type + separated-type)`. |
| `dist_to_nearest_outfall_m` | Distance (meters) from the ward's centroid to the nearest sewer outfall (where flow exits into a river or the lake). **Does not vary by year.** | Euclidean distance in a metric CRS (EPSG:2952) between the ward's centroid and the closest outfall point — computed once for each ward, since outfalls have no recorded installation date to filter by. Same value repeated in all 9 years for that ward. |

## Assumptions / known limitations

- Pipes/inlets/manholes crossing a ward boundary are assigned using the pipe's midpoint (lines) or the point's exact location (inlets/manholes/outfalls) — same simplification as the 25-ward panel.
- 119 of 164,685 pipes (0.07%), 696 of 173,798 inlets (0.4%), and 125 of 160,640 manholes (0.08%) fell outside all ward polygons (edge of the covered area) and are excluded. These counts are similar in magnitude to the 25-ward panel's, since both ward systems cover roughly the same area of Toronto (~641 km² total for the 44-ward boundaries).
- **`Sewer Inlets` has 15.4% of rows matched to a ward (26,669 of 173,102) with no valid installation date.** Those rows can **never** be counted in `catch_basin_density`, in any year — because there's no date to compare against `install_year <= year`.
- `Sewer Manholes` has only ~1.9% nulls in its install date — a much smaller effect on `manhole_density` and `pct_combined_manholes`.
- `Sewer Outfalls` has no installation-date column at all, so `dist_to_nearest_outfall_m` can't vary by year — a real data limitation, not a design choice.
- This file deliberately excludes `Trunk Sewer` (same decision as the 25-ward panel), so `pipe_density` and `avg_pipe_diameter` are slightly lower than a trunk-inclusive version would be.
- The 44-ward boundaries (`before_2018_ward_location.csv`) and the 25-ward boundaries (`City Wards Data - 4326.geojson`) are **not directly comparable row-by-row** — they're different polygons covering the same city at different points in time. No crosswalk between them has been built yet.

## Validation performed

- 396 rows (44 wards × 9 years), 0 nulls across all 16 columns.
- `cumulative_pipe_km` confirmed non-decreasing across all 44 wards.
- Sanity check: Ward 27 (Toronto Centre-Rosedale, historic downtown) has `pct_combined_sewer` consistently ~63.8% with `avg_pipe_age` rising from 70.2 to 78.1 years (2010→2018), vs. Ward 43 (Scarborough East, suburban) at `pct_combined_sewer` = 0% with `avg_pipe_age` from 44.2 to 52.1 years — the same historic downtown-vs-suburb pattern already confirmed in the 25-ward panel.
